# Results Analysis Design

**Date:** 2026-08-02  
**Status:** Approved design

## Goal

Add a reproducible CLI-driven data science analysis for detector results. The analysis will compare detector and architecture combinations using fold-level observations, produce boxplots and summary charts, export analysis CSV files, and write an English Markdown findings report.

## Usage

```bash
python cli.py analyze \
  --results results/yolov8_faster \
  --output analysis/yolov8_faster
```

The command is read-only with respect to raw result files.
The output directory must be outside the raw results directory so generated files
cannot be discovered as input results on a later run.

## Input Data

The loader accepts:

- `summary.csv` generated by the sweep runner.
- Nested `metrics.json` files as a fallback when `summary.csv` is unavailable.
- Legacy `ml` identity columns as well as `detector` and `architecture` columns.

Each fold-level result is one statistical observation. Model identity is normalized into a stable detector/architecture combination.

## Output Structure

```text
results/.../analysis/
├── charts/
│   ├── boxplot_map.png
│   ├── boxplot_map50.png
│   ├── boxplot_map75.png
│   ├── boxplot_mae.png
│   ├── boxplot_rmse.png
│   ├── boxplot_precision_recall_f1.png
│   └── metric_means.png
├── normalized_results.csv
├── descriptive_statistics.csv
├── model_ranking.csv
├── fold_completeness.csv
└── findings.md
```

## Metrics

The analysis recognizes these metrics when present:

- `mAP`
- `mAP50`
- `mAP75`
- `MAE`
- `RMSE`
- `precision`
- `recall`
- `f1`
- `pearson_r`

Missing metrics remain missing and are reported. They are not silently imputed.

## Statistical Analysis

The report and CSV outputs will include:

- Count, mean, median, standard deviation, minimum, maximum, first quartile, and third quartile per detector/architecture/metric.
- Interquartile range as a robust variability measure.
- Rankings for every available metric.
- An overall normalized score across available metrics.
- Stability analysis using standard deviation and interquartile range.
- Best and worst model per metric.
- Fold completeness and missing-data warnings.

Higher-is-better metrics are scored positively. `MAE` and `RMSE` are inverted before calculating the overall score because lower values are better. The report will clearly label the direction of each metric.

The report will make descriptive claims only. It will not claim statistical significance without sufficient independent fold observations.

## Charts

Boxplots will use model/architecture combinations on the x-axis and folds as observations. Separate charts will be generated for mAP metrics, error metrics, and classification metrics. A mean comparison chart will summarize central performance across metrics.

Charts will use a non-interactive Matplotlib backend so the command works on servers and in automation jobs. Labels will be rotated or wrapped to remain readable for many model combinations.

## Validation and Error Handling

Before analysis, the command validates:

- The results directory exists.
- At least one supported result source exists.
- Identity columns are present or inferable.
- Metric values are numeric when present.
- Duplicate rows are reported.
- Incomplete model/fold combinations are preserved and flagged.

The command fails with a clear error when no usable result data exists. It warns, rather than fails, for incomplete folds and optional missing metrics.

## Testing

Tests will cover:

- Loading `summary.csv`.
- Loading nested `metrics.json`.
- Normalizing legacy `ml` columns.
- Grouping fold-level observations.
- Correct ranking direction for performance and error metrics.
- Missing metrics and incomplete folds.
- Generated CSV, chart, and Markdown outputs.

## Integration

The analysis will live in a focused `analysis/` package and be exposed through the existing `cli.py` as an `analyze` subcommand. It will not modify training, evaluation, or raw result generation behavior.
